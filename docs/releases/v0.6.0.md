# MorningstarModbusAPI v0.6.0

v0.6.0 is a feature release focused on making controller-retained history operationally useful after reconnects and telemetry outages.

## Highlights

- Adds controller-scoped day-level history coverage reporting that distinguishes persisted live polling from controller-retained evidence.
- Adds gap reconciliation views that classify missing days as `recovered`, `partial`, or `missing` without fabricating high-frequency samples.
- Adds daily controller energy accounting that keeps Morningstar-reported daily Wh separate from locally integrated `output_power` telemetry.
- Uses gap-bounded trapezoidal integration so long outages are skipped instead of assuming power remained constant through missing intervals.
- Adds controller-vs-local energy discrepancy metrics that help identify incomplete telemetry, persistence gaps, and integration bias.
- Preserves immutable `controller_uid` scope and raw `source_device_id` provenance throughout the new analytics surfaces.

## New controller API routes

- `GET /v1/controllers/{controller_uid}/history/coverage`
- `GET /v1/controllers/{controller_uid}/history/gaps`
- `GET /v1/controllers/{controller_uid}/energy/daily`
- `GET /v1/controllers/{controller_uid}/energy/summary`

## Compatibility and safety

The release remains read-only. Controller-retained daily records are not inserted into `poll_samples`, and the API does not reconstruct telemetry that was never observed. Existing controller-, device-, and system-scoped endpoints remain available.

## Upgrade notes

No destructive database migration is required for the new analytics layer. Existing installations can upgrade normally; the new endpoints operate over the controller-retained daily-history and persisted poll data already maintained by the service.
